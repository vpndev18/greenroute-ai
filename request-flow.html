GreenRoute AI · technical walkthrough

How a prompt moves through GreenRoute

GreenRoute is a carbon-aware router for LLM requests. A FastAPI service on Cloud Run makes three decisions for every prompt, runs it on Gemini, and writes a carbon ledger to Firestore. The browser reads that ledger live.

Which modelGemini Flash-Lite classifies the prompt as simple, medium or complex. That maps to the Lite, Flash or Pro tier.classify()
WherePick the region whose grid has the lowest gCO₂/kWh. In India-only mode, only Mumbai and Delhi are allowed.plan_slot()
WhenDeferrable jobs search 30-minute slots up to the deadline and go through Pub/Sub.plan_slot() + /api/worker

The carbon maths

Every number on the receipt comes from these four functions in backend/main.py. The constants are per 1,000 output tokens, and input tokens cost one tenth as much.

# hourly grid intensity: annual average with a solar dip centred at 13:00 local time
intensity(region, t) = annual × (1 − amp × cos(2π (local_hour − 13) / 24)),  amp = 0.04 + 0.14 × (1 − cfe)

# energy, including data-centre overhead (PUE 1.09)
energy_Wh = 1.09 × (in_tokens × c / 10 + out_tokens × c) / 1000,   c = 0.25 (lite) · 0.60 (flash) · 2.50 (pro)

co2_g      = energy_Wh / 1000 × intensity
baseline_g = energy_Wh(pro, same tokens) / 1000 × intensity(asia-south1, now)
saved_%    = (baseline_g − co2_g) / baseline_g

Worked example: "Translate 'good morning' into French"

About 25 input tokens and 20 output tokens. Triage says simple, so the Lite tier runs in Montréal (about 2 gCO₂/kWh).

GreenRoute: Lite in Montréal0.0061 Wh≈ 0.00001 g CO₂
Baseline: Pro in Mumbai (648 g/kWh)0.0613 Wh≈ 0.040 g CO₂
Saved≈ 99.9%10× from tier choice, about 300× from region choice

Mumbai's figure varies a little with time of day because of the solar-dip model. The tier ratio (2.5 ÷ 0.25) and the grid ratio multiply together, which is why both decisions matter.

Prototype limits

  • Grid intensity is modelled. It uses Google's 2023 annual figure per region with a synthetic solar curve. A production version would read Electricity Maps or WattTime.
  • Deferred jobs run when they arrive. Pub/Sub delivers within seconds, and the carbon is calculated at the planned slot. Real delay needs Cloud Tasks with a schedule_time.
  • Fallback to global loses location. When no region in the allowed list serves the tier, the call goes to the global endpoint and is counted against us-central1. India-only requests can end up there.
  • Energy per token is an assumption, calibrated to Google's published median of about 0.24 Wh per Gemini text prompt.
  • The API is open. CORS is *, Cloud Run allows unauthenticated calls, and there is no rate limit.
